A modified fork of the original Bravely Default Randomizer by [MarvinXLII](https://github.com/MarvinXLII/BravelyRandomize.git).

This fork adds generation of a visual HTML format of the spoiler log generated by the base executable. 

My personal favorite way to play these games is a sort of *four-job-fiesta* style where each character is locked to one of the four unlockable jobs in the prologues. In addition, I self-assign level caps (both character and job levels) for each chapter - typically 2/3 job levels per chapter. But since job-leveling is an annoying process to do after each chapter, I prefer to play the randomizer with all jobs mastered. However, this makes tracking which abilities I am actually allowed to use difficult with just the base spoiler text file. Hence, I created a more functional HTML format to ease cross-referencing.

The HTML spoiler log allows:

- Select jobs to display, such as the jobs/commands currently equipped by the party, or only unlocked jobs

- Select the current job level (the cap) to gray out all unavailable abilities at that level

- Color coded abilities (orange for command, blue for support, red for magic, and gray for *not unlocked*)

- Hover the cursor over any ability to display and read its description. Magics will list the correct randomized spells

- More flavorful design of other sections

If you want to build the app yourself, download and exctract the repo, then use [PyInstaller](https://pyinstaller.org/en/stable/) and run 

```bash
cd path/to/project
pyinstaller gui.spec
```

This will create the executable along with needed additional files.

Otherwise, just download and extract the file from the releases. This includes the executable and `assets` used for images and ability tooltips. Make sure that `assets` folder exists in the same directory as the executable when running and creating a randomizer patch with the executable or it will hang. Additionally, the app will not automatically copy over `assets` to `patch_<game>_<number>` upon generation. The HTML file in the `patch_<game>_<number>` will function, but will be missing the images and ability tooltips. If you do not care about those, then you may forego copying over `assets`. Otherwise, you should copy over `assets` to `patch_<game>_<number>` (or just create an empty `assets` folder within `patch_<game>_<number>` and copy over only `assets/<game>` to `patch_<game>_<number>/assets`).

### ABOUT

This is a randomizer for Bravely Default: Where the Fairy Flies and
Bravely Second: End Layer. It has been built and tested only on North
American releases.

### OPTIONS

Several options are available for both games:

- Shuffle job abilities (commands, spells, and support skills).

- Random job specialties

- Shuffle job stats ("affinities")

- QOL: Scale experience, JP, and pg earned from battles.

A few options are only available to specific games (unfortunately).

- Shuffle treasure chests and hidden items (only Bravely Default)

- Shuffle job equipment stats ("aptitudes") (only Bravely Second)


### USAGE

To run the executable from the Releases page, it is assumed that you
have [extracted RomFS from your
cartridge](https://gist.github.com/PixelSergey/73d0a4bc1437dbaa53a1d1ce849fdda1).
It will not work with `*.3ds`, `*.cia`, etc. files. The executable
requires that you input the path to (and including) the folder
`romfs`.

The executable outputs a directory entitled
```patch_<game>_<number>```, e.g. ```patch_BD_42``` is an output for
Bravely Default with seed 42. This folder contains a spoiler log, a
file `settings.json`, and a folder `romfs`. The settings file is a
record of selected options. The `romfs` folder is the patch generated
for your game. It can be run on your console with [Luma
LayeredFS](https://gist.github.com/PixelSergey/5dbb4a9b90d290736353fa58e4fcbb42).

During gameplay, _**your Text Settings must be set to English**_ for any of your patches to work.

### KNOWN BUGS

Bravely Second: Janne and Nikolai do not have animations for all possible abilities, leading to crashes during battles. Stick with just basic attacks when they are in your party. You may need to toggle off your patch until they leave your party if crashes persist.
